## Concrete delivered slice

Separate unpackaged x64 companion packaging preserves existing release/MSIX tools. `New-BrowserBundle.ps1` consumes an existing self-contained x64 host publish, builds browser-specific extension directories/ZIPs, emits exact native manifests, copies registration/staging tools plus matching restored .NET10.0.9 declared notices/dependency inventory, and verifies a complete SHA-256 inventory. No GUI, app runtime/history, preferences, native descriptor or app UUID is packaged. Unknown/private/reparse content fails integrity checks. The inventory is unsigned and does not authenticate provenance; full runtime/native redistribution review remains pending.

`Register-BrowserHost.ps1` requires channel/browser/install-root; development defaults to dry-run/readback. Release is not an accepted channel, and development Apply is blocked. Synthetic Apply requires unique names under HKCU Software/AriaGUI/Verification/UUID, outside browser discovery. Both32/64 views are planned explicitly. The module rechecks inventory and rederives entries on every operation, rejecting stale/tampered plans. Install/repair captures previous defaults, reads back exact REG_SZ, restores only still-owned writes on failure, and preserves changed/foreign values. Uninstall removes only the matching default, keeps other values/subkeys/channels, and reports a partially completed multi-key removal as safely retryable. It does not claim OS atomic compare-and-swap against malicious same-user races. Missing/corrupt bundle blocks automatic operations rather than silently unregistering unrelated pointers.

`Install-BrowserCompanion.ps1` provides real file staging/repair/readback/uninstall, **only** inside a selected checkout `artifacts/browser-installer-tests/UUID` synthetic scope. Dry-run performs read-only source/ownership/containment/active-process preflight. Apply verifies a private sibling copy before allowed native-path rewrites, checks its complete inventory, refuses active payload executables, moves through a rollback backup, writes an external ownership receipt, and preserves companion identity during repair. Every recursive mutation target is resolved and checked inside the selected scope; unknown payload files block deletion. History/runtime outside payload are untouched. Post-switch injected failure restores exact old payload/receipt. Abrupt termination across directory/receipt switches is not crash-atomic; orphan stage/backup/receipt recovery remains manual verified work. The companionInstallationId is an ownership identity, not v1's app runtime installationId. Real per-user production paths/descriptor generation remain blocked, not merely enabled by this helper.

App preferences add optional browser settings with disabled/null/empty defaults; old JSON remains compatible. Selected app UUID and local installation root validate without secrets/URLs. Existing full-save/layout serialization preserves saved browser metadata instead of unsaved drafts. Settings show a disabled enable checkbox, selected metadata, readiness check and public-GET/privacy explanation. No production hello transport is composed. A normal check can distinguish selection/host missing/release blocked; it never launches user-selected code or treats registry presence as connected. The diagnostic service's ready path requires a correlated closed compatible hello with expected capabilities/size and receives the selected app UUID; deterministic injected replies test that boundary. **No real GUI hello is claimed here.** Extension presence cannot be proven by the GUI without a trusted browser-side handshake; UI explicitly says unverified. Actual settings visual/interaction acceptance is unverified.
