## Implemented

- Version-2 capability/PID-authenticated loopback route and version-3 immutable strong representation. aria2 1.37.0 begins a split transfer with a full GET; the route validates its known-length, identity-encoded, strong-ETag 200 before exposing bytes and then accepts exact bounded intervals, including zero. Version-1 rejects arbitrary bounded/suffix/malformed ranges before origin contact but admits a resume tail only when the previously authenticated representation proves its end is EOF. The public origin transport carries the exact Range through approved redirect hops.
- Bounded interval relay compares 206, effective resource, strong ETag, total, Content-Range, Content-Length, encoding, and non-multipart type against the immutable representation. It buffers each bounded body (maximum eight MiB) before downstream delivery and rejects short/extra bodies. First-response representation commit uses a short lock; disjoint bodies overlap; duplicate/overlapping active bounded intervals are rejected before origin contact, and cancellation is per request. The gateway has a 16-connection limit and each relay admits four requests. The public origin transport also admits at most 16 active responses globally and four per actual redirect-hop host/port across routes. Real-socket testing exposed a socket-pool lease release delay; admission is now attached to response disposal, with DNS/address validation still performed at connection time.
- Durable SQLite `HttpConnections` (default 1 for migration of old attempts) and transfer-journal version/count bind the selected fixed policy to each attempt. Manager requires opt-in, guarded staging, durable repository intent, and expected SHA-256 before v2 dispatch; RPC uses 2/4 `split` and `max-connection-per-server` with `min-split-size=1M`. Both restore and re-add preserve the count. A disabled flag holds existing parallel attempts; it does not downgrade them to v1 or direct origin. Sequential/v1 records reject v3 representation records.
- Paused/failed/removed v2 observations capture quiescent private payload/control pairs when file metadata or authenticated completed count changes, avoiding a full copy/hash on every unchanged poll. A strict aria2 v1 HTTP control parser checks piece/in-flight-chunk coverage and compares it with authenticated RPC `completedLength`. Revisioned snapshots hash both files, so unchanged length with changed bytes advances revision. Each attempt has a private snapshot directory; after a durable pointer update, old revisions are pruned. Crash-orphan revisions are pruned on restore. Restore validates the snapshot, representation total and policy, then copies into a new private work directory; the abandoned pair remains untouched. Invalid or missing snapshots hold the attempt. Completion still requires authenticated engine completion, guarded staged file identity, exact full-file expected SHA-256 and the existing durable publication journal before the public file becomes Completed.

## Release decision

M3 acceptance is closed. The correctness, preservation, fault, connection-budget, application, build, and final interactive gates have passed. Shipping application composition enables the guarded fixed 2/4 capability. After default enablement, `dotnet build AriaGui.slnx --no-restore -m:1 -nr:false -v:minimal` passed with zero errors; its two NU1900 warnings were limited to the unavailable NuGet vulnerability-data service. Loading the built Infrastructure assembly and invoking `Aria2ProcessOptions.ForApplication` confirmed both `UseContinuityGateway=True` and `ParallelHttpRanges=True`. A new focused regression test compiles, but two invocations were aborted before discovery because `vstest.console` could not connect to `testhost` within 90 and 180 seconds; no assertion failed, and this runner issue does not replace the earlier passing M3 and full Application matrices.

The exact expected digest remains mandatory for parallel attempts, and unsupported representations remain excluded by the guarded transport. The owner-process kill matrix stops at the five named journal boundaries rather than every instruction-level crash window; durable replay and file-identity gates cover intermediate states. The actual public-origin test uses an injected DNS/socket connector to an owned loopback TCP origin, exercising HTTP serialization, redirects and response lifetime without contacting public internet hosts.
