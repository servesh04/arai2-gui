# Phase C isolated deployment acceptance

This prepared bundle is not acceptance evidence. It contains the reviewed development-signed candidate and its public certificate; no host trust or install is changed. `New-PhaseCSandboxBundle.ps1` creates an offline `.wsb` with read-only inputs and only its fresh output folder writable. The startup script performs readiness checks only. Windows Sandbox must already be enabled by the test-environment owner. Configuration follows [Microsoft's Sandbox guidance](https://learn.microsoft.com/en-us/windows/security/application-security/application-isolation/windows-sandbox/windows-sandbox-configure-using-wsb-file).

Use a disposable owned guest. Never substitute the user's desktop. The username/host-name check prevents accidental host execution; it does not authenticate an arbitrary remote machine. Keep input hashes, OS, SDK, package identity and browser version in the evidence. Readiness must pass before importing the public certificate into the **guest's** LocalMachine TrustedPeople store and installing `C:\PhaseCInput\candidate.msix` with Add-AppxPackage. Record both commands' success or exact failure. The development certificate does not establish shipping publisher trust.

## Required observations

1. On a clean offline guest, install without downloading dependencies. Record package identity and manifest protocol. Run the installed Start-menu entry with no arguments; exercise canonical `ariagui://open` using shell and the guest's browser. Record cold/warm/Close-to-tray restoration and sole GUI/engine ownership. A Release process has no synthetic receipts: do not infer Protocol adaptation or rejection from an exit code. A separately built verification candidate is necessary for safe activation-kind reason receipts.
2. Exercise mixed case, root slash, query, fragment, percent encoding, extra path, whitespace, quotes and extra arguments. Record source versus delivered value only in the controlled capture fixture. Check rejected cold inputs leave runtime files unchanged and rejected warm input leaves the minimized owner unchanged. Browser external-protocol prompts need an operator; absence of a prompt response is incomplete, not rejection.
3. Restart only the guest's Explorer while the app is in the tray, then verify icon re-registration, open-link restoration and usable taskbar fallback. Record actual shutdown interleave and deliberate relaunch. Reuse the marked private-port pinned-engine fixture for pending identity recovery; do not route its port setting through URI/CLI.
4. Repeat unpackaged activation using the [installable review candidate](BROWSER_HANDOFF_PHASE_C_UNPACKAGED_INSTALLER.md): `Install-OpenProtocol.ps1` owns `%LOCALAPPDATA%\AriaGUI\OpenOnly\app\AriaGui.App.exe` with serialized staging/journal/recovery. Copy its complete prepared Release payload and tools into the guest; dry-run before `-Apply`. Record upgrade and rollback binaries, interrupted-write recovery, missing target, uninstall after binary removal, foreign/changed value/type preservation, actual coexistence with the package and Windows default-choice behavior. Package conflicts intentionally refuse shadowing; test Windows choice separately. Never write UserChoice directly. Shipping shortcut/bootstrapper distribution is still a release packaging decision; this candidate does not create Start-menu shortcuts. C-G3 requires recorded actual installer acceptance, not only the synthetic suite.
5. Remove only the just-installed package by its exact captured package full name, remove only the just-imported test certificate thumbprint, and remove any exactly owned unpackaged registration. Verify package/handler/certificate/process cleanup. Save evidence in `C:\PhaseCOutput`, then discard the guest. No host Explorer restart or host certificate cleanup is needed because neither was changed.

The offline Sandbox covers ephemeral clean-machine dependency/activation work, not persistent upgrade or reboot acceptance. Use an owned persistent VM snapshot for installer rollback/reboot cases. Do not label preparation, readiness or successful signature inspection as passing C-G1/C-G3.
