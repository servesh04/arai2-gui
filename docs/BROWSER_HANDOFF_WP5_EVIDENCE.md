# Browser handoff Package 5: explicit public-link extension MVP

2026-10-12, layered on uncommitted Package 4. No commit, personal browser installation, registry write, production GUI activation, new protocol/schema or installer was introduced.

## Implementation

`extensions/aria-gui` is one dependency-free ES-module source tree with typed protocol declarations, strict runtime v1 validation, serialized native-port client, background controller, popup/options, and a reproducible Node22+ generator. Locked package metadata declares no npm dependencies and no invented distribution license. Native API objects are validated against the closed schema and expected correlation; unknown fields/codes or wrong correlation cannot become acceptance. Shared v1 fixtures exercise the production validator, including Unicode/signed URLs, forbidden headers and malformed requests/responses.

Chrome and Edge artifacts use MV3 module service workers. Firefox uses MV3 nonpersistent scripts/event page; its classic adapter installs listeners synchronously before dynamic-importing shared modules. Both register click/message/startup listeners synchronously. The Firefox menu API has a separate creation path rather than a Chromium callback adapter. UI control messages accept only the extension's own popup/options, no tab/content/external senders. No external messaging listener, content script, automatic capture, host permission, cookies, download interception or arbitrary command exists.

Permissions are exactly nativeMessaging/contextMenus/storage. Context menu is link-only with HTTP(S) patterns; runtime validation repeats scheme/userinfo/length/control checks and preserves exact signed source string apart from removing the fragment. Authoritative application network policy remains separate. Default enablement is false. Options explicitly select an app installation UUID, test connection and show safe status/version. UUID discovery/installer setup is Package 6 work. Native templates contain exact generated development origins/add-on ID and an unresolved executable-path placeholder; they cannot install themselves. Chrome/Edge development keys intentionally use the same pinned fixture key; production/store identities are not supplied.

Persisted state contains enablement, selected app UUID, a locally generated extension-instance UUID, up to 32 unresolved request UUIDs/app UUIDs/timestamps/state and safe UI status/job ID. No URL, filename, cookie, header or raw error is persisted or logged. The extension-instance UUID is not sent as v1 installationId: v1 selects the app UUID. Per-browser/profile/extension-install ledger isolation (E05) remains unresolved and is not widened by this package.

A gesture persists its pending UUID before potential Add. Persistence failure prevents Add. Add is sent once, with one request in flight. Durable accepted is the only route to “Added to AriaGUI”; this is not transfer completion. Host/timeout/worker loss leaves “Cannot confirm.” On worker wake/manual check, query the same target UUID, never replay Add. not_found/processing/unknown/unavailable preserve ambiguity because a late transaction may still commit. Each reconciliation handles at most eight and rotates unresolved IDs so later IDs are not starved. At 32 unresolved IDs, admission refuses rather than discarding pending work. Local brief duplicate callbacks are suppressed in the live worker; app idempotency remains authoritative. Cross-worker duplicate gesture callbacks and manual fresh resubmission after uncertainty are not promised duplicate-free.

Private context clicks return before storage/native activity; private UI messages/wake are refused, and generated manifests set incognito not_allowed. Browser-download work is never canceled. Popup explains public GET, retained app history and unsupported authentication/POST/blob/private capture; destination conflicts show manual rename guidance.

## Current official documentation checks

- [Chrome native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging) and [Edge native messaging](https://learn.microsoft.com/en-us/microsoft-edge/extensions/developer-guide/native-messaging): nativeMessaging permission and connectNative port in extension background/page context.
- [Chrome service-worker lifecycle](https://developer.chrome.com/docs/extensions/develop/concepts/service-workers/lifecycle): worker lifetime is transient; persisted IDs and status recovery replace reliance on memory/keepalive. Chrome minimum120 is a manifest floor, not an acceptance-certified version.
- [Firefox background manifest](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background): service_worker unsupported; scripts/event-page adapter generated separately.
- [Firefox native messaging](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Native_messaging): native manifest path/add-on ID invocation is separate from Chromium origin, already enforced by Package 4. No new registration here.
- [Firefox consent requirements](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/) and [browser-specific settings](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/browser_specific_settings): Firefox desktop140+ supports built-in consent. The development manifest declares required websiteContent because links are transmitted outside the extension to the app; it does not falsely declare none. Actual Firefox install/consent/store/privacy review is unverified.
