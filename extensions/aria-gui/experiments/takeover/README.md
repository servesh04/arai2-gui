# A1 browser-free experiment

These modules are outside `src` and are not copied by `build.mjs`. There are no browser globals, listeners, new permissions, wire actions or application registration. `FixtureWorker` defaults to disabled and permits effects only when browser, app and issuer dependencies all identify as fixtures. This guard prevents accidental use in this harness; it is not a security boundary against modified extension code.

`state.mjs` is the independent reducer and strict durable-record schema. `adapters.mjs` exposes the injected `readFresh(itemId)`, `pause(itemId)` and `cancel(itemId)` interface and normalizes Chrome/Edge/Firefox snapshots. `fixture-worker.mjs` executes the reducer against synthetic in-memory dependencies. Future live adapters and a versioned app protocol require separate review and real browser acceptance.

The controlled issuer establishes public repeatable GET semantics independently of a DownloadItem. Its immutable grant ID binds issuer/revision, exact source and filename, caller/install/profile/item/start identity and expiry. Grants and resource/name remain in the issuer's memory, never in the recovery ledger. Recovery needs the same trusted immutable issuer registry (or separately reviewed equivalent); losing it stops mutations. There is no issuer reconstruction from stored flags or generic browser events. A real controlled-source integration must prove cookie/auth absence and request semantics; these fixtures only declare synthetic context.

The ledger holds version, UUID identities (including opaque grant ID), browser/item/start identity, phase, timestamps, attempted-effect flags and stable accepted job ID. UUID validation and a closed schema reject raw URLs, filenames, headers, arbitrary errors and extra fields. It retains at most 32 rows; accepted/terminal rows are preserved until deliberate lifecycle handling. Capacity refuses new work; no automatic eviction or transfer recreation.

Every first pause/cancel attempt is persisted and awaited before the injected operation. Pause is optional. Recovery queries the same app request key once, re-reads the browser item and reacquires a valid grant. Acceptance is monotonic and can be discovered even if the browser item disappears. Cancellation intent plus a fresh unchanged `interrupted`/`USER_CANCELED` observation permits the synthetic idempotent commit. A fulfilled cancel call, completed/disappeared item or other interruption does not. A death after intent persistence but before cancel leaves an in-progress item unresolved rather than retrying cancellation. Unknown, aborted and expired outcomes retain history and guidance; this slice does not automatically resume, erase, restart or make a replacement request.

`USER_CANCELED` has no attributable cancellation token: another actor can win the race after our durable intent. These mappings do not eliminate that residual uncertainty. An actual browser test must establish the controlled integration and quantify races before activation. See [A1 evidence](../../../../docs/BROWSER_HANDOFF_A1_EVIDENCE.md).

The positive Firefox fixture is an enriched synthetic snapshot with an explicit effective source. Mozilla's documented DownloadItem does not supply Chromium's `finalUrl`; native snapshots lacking it are refused. There is no `url` fallback or live Firefox effective-source provider in this slice. A separately proven controlled integration must close this gap before Firefox eligibility is claimed.
